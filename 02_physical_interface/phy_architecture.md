# PHY Architecture

This section covers the architecture of the LPDDR PHY (Physical Interface), which is the block on the SoC that implements the physical signaling interface to the DRAM. Understanding PHY architecture is essential for layout engineers because the PHY is a mixed-signal block with demanding placement and routing requirements.

---

### Q1. What are the major functional blocks within an LPDDR5 PHY, and how are they organised?

**Answer:**

An LPDDR5 PHY consists of several major functional blocks organised hierarchically. At the top level, the PHY contains a PLL (Phase-Locked Loop) or DLL (Delay-Locked Loop) that generates the multi-phase clocks needed for serialisation and deserialisation. The PLL takes a reference clock (typically 100-400 MHz) and generates the high-frequency clocks at the data rate and its subdivisions.

Below the PLL, the PHY contains one byte lane per 8-bit data channel. Each byte lane includes 8 DQ IO cells (one per data bit), 1 DQS differential IO cell (for the data strobe pair), serialisers that convert the wide parallel data from the memory controller into serial bit streams, deserialisers that convert incoming serial data back to parallel format, read/write FIFOs that buffer data between the controller clock domain and the IO clock domain, delay lines for per-bit deskew (digitally controlled delay elements), and VREF generators for setting the receiver threshold.

The PHY also contains a CA (Command/Address) lane per channel, which includes 7 CA IO cells, 1 CK differential IO cell, and 1 WCK differential IO cell. The CA lane has its own serialiser for double-data-rate CA transmission.

A shared ZQ calibration block connects to an external precision resistor and calibrates the impedance of all IO cells. The training controller (finite state machine) orchestrates the various training sequences (read leveling, write leveling, VREF training, WCK2CK training).

The DFI (DDR PHY Interface) block provides the standardised interface between the PHY and the memory controller, handling protocol conversion and timing adaptation.

Physically, these blocks are arranged with the IO cells at the die edge (closest to the package bumps), the serialisers and delay lines immediately behind the IO cells, the FIFOs and training logic in the next tier, and the PLL and DFI interface blocks closest to the core logic area.

### Q2. How does the DQ byte lane work internally, and what are the key circuits in each lane?

**Answer:**

A DQ byte lane handles all aspects of data transmission and reception for 8 DQ bits and their associated DQS strobe. The internal architecture of a byte lane can be divided into transmit (write) and receive (read) paths.

On the write path, the memory controller presents 128 bits of write data per byte lane (8 DQ x 16 bits prefetch) at the DFI clock rate. This data enters the write FIFO, which absorbs timing differences between the controller and IO clock domains. The serialiser then selects one bit at a time from each DQ's 16-bit prefetch, using multi-phase clocks derived from the PLL to generate the correct timing. The serialised bit drives the IO cell's pre-driver, which feeds the output driver. The DQS strobe is generated by the PHY in alignment with the write data, using the write leveling calibration offset to ensure correct arrival at the DRAM.

On the read path, the DQS receiver detects the incoming strobe from the DRAM. The DQS passes through a variable delay line (set during read leveling training) and then clocks the DQ samplers. Each DQ receiver uses the delayed DQS as its sampling clock, capturing data at the centre of the DQ eye. The captured data enters the deserialiser, which assembles 16 consecutive bits (for BL16) into a parallel word. This parallel data enters the read FIFO, which transfers it to the controller clock domain.

Key circuits within each byte lane include per-bit delay cells that allow fine adjustment (typically 1-5ps step resolution) of each DQ's timing relative to DQS, enabling per-bit deskew to compensate for routing asymmetries. The VREF generator provides a programmable reference voltage to each DQ receiver, adjustable during VREF training. Duty cycle correctors on the DQS path ensure the DQS duty cycle is close to 50%, maximising the sampling window for both rising and falling edges.

For layout, the byte lane is the fundamental unit of placement. All circuits within a byte lane should be placed as a compact group, with the IO cells aligned at the die edge and the supporting logic arrayed behind them. The internal routing between the delay cells, serialisers, and IO cells must be short and matched to preserve the calibrated timing.

### Q3. What is the role of the PLL/DLL in the LPDDR PHY, and how does its placement affect layout?

**Answer:**

The PLL (Phase-Locked Loop) generates all the high-frequency clocks needed by the PHY. Starting from a reference clock (typically 26 MHz, 38.4 MHz, or similar crystal-derived frequency), the PLL multiplies this to produce clocks at the CK frequency, the WCK frequency (2x or 4x CK), and multiple phases of the data-rate clock for the serialisers and deserialisers. The PLL also generates divided clocks for the DFI interface and internal logic.

Some PHY architectures use a DLL (Delay-Locked Loop) instead of or in addition to the PLL. A DLL takes an input clock and generates multiple phase-shifted versions of it, without frequency multiplication. DLLs are simpler and lower-power but cannot generate clocks at frequencies different from the input.

The PLL is one of the most layout-sensitive blocks in the PHY because it is an analog circuit with stringent jitter requirements. The clock jitter from the PLL directly impacts timing margins for every signal in the interface. Key layout considerations include isolation from digital switching noise, because substrate noise coupling from nearby digital logic can modulate the PLL's voltage-controlled oscillator (VCO), creating jitter. The PLL should be placed in a quiet region of the die, surrounded by guard rings that isolate it from substrate noise. The power supply for the PLL must be filtered and separate from the noisy digital supplies. Dedicated VDD and VSS pins (or at minimum, dedicated on-chip regulators) should feed the PLL, with extensive decoupling. The PLL output clock distribution network must be low-skew, delivering clocks to all byte lanes with matched delay. This often requires an H-tree or balanced clock tree routed on dedicated metal layers.

The PLL is typically placed centrally relative to the byte lanes it serves, so that the clock distribution paths to each byte lane are approximately equal. Placing the PLL at one end of the PHY would create a systematic skew between near and far byte lanes.

### Q4. How do read and write FIFOs function in the PHY, and what are the layout implications?

**Answer:**

Read and write FIFOs provide elastic buffering between two clock domains: the memory controller clock domain and the IO (data rate) clock domain. These domains operate at different frequencies and have an unknown phase relationship, making the FIFO essential for reliable data transfer.

The write FIFO accepts wide parallel data from the memory controller (via the DFI interface) at the controller clock rate and provides it to the serialiser at the IO clock rate. The FIFO depth is typically 4-8 entries, where each entry is one burst-worth of data (128 bits per byte lane for BL16). The write pointer advances with the controller clock, and the read pointer advances with the IO clock. The FIFO must handle the case where the two clocks have different frequencies (the controller clock may be slightly faster or slower than the IO clock divided by the serialisation ratio).

The read FIFO receives parallel data from the deserialiser at the IO clock rate and presents it to the memory controller at the controller clock rate. The read FIFO is slightly more complex because the read DQS clock (which drives the deserialiser) has an uncertain phase relationship to the system clock, determined by the flight time from the DRAM.

For layout, the FIFOs occupy significant area within the PHY and must be placed between the serialiser/deserialiser and the DFI interface boundary. Key considerations include timing closure on both clock domains. The write side of the write FIFO must meet setup and hold times with respect to the controller clock, while the read side must meet timing with respect to the IO clock. Similarly for the read FIFO. The physical placement must minimise wire delays on both sides. The FIFO memory cells (typically static register files or SRAM) should be placed compactly to minimise internal delays. Clock distribution to the FIFOs must be clean, with both the controller clock and the IO clock arriving with low skew across the FIFO. The pointer logic (gray-coded pointers for clock domain crossing) must be placed close to the FIFO memory to minimise the delay in the pointer comparison path.

### Q5. What is ZQ calibration, and how is it implemented in the PHY layout?

**Answer:**

ZQ calibration is the process of setting the output driver impedance and on-die termination (ODT) resistance to match the target values specified by the JEDEC standard. The name comes from the ZQ pad, which is connected to an external precision resistor (typically 240 ohm to ground) that serves as the impedance reference.

The calibration process works as follows: the ZQ calibration circuit contains a replica of the IO driver connected to the ZQ pad. During calibration, the circuit adjusts the driver's impedance code (by switching in or out parallel transistor legs in the driver) until the voltage at the ZQ pad equals VDDQ/2, which occurs when the driver impedance matches the external resistor. This calibrated code is then distributed to all IO cells in the PHY, which use it to set their driver strength and ODT values.

LPDDR5 defines several ZQ calibration modes: ZQCL (long calibration at initialisation), ZQCS (short calibration during operation for tracking temperature drift), and background ZQ calibration. The calibration must be periodic because the transistor impedance varies with temperature (approximately 0.3-0.5% per degree Celsius).

For layout, ZQ calibration has several important requirements. The ZQ pad must have a dedicated bump with clean routing to the external precision resistor. The routing should avoid coupling from switching signals that could corrupt the voltage measurement. The replica driver in the ZQ block must be a faithful copy of the actual IO drivers, including the same transistor dimensions, metal routing, and parasitic environment. Any mismatch between the replica and the actual drivers will create a systematic impedance error. The code distribution from the ZQ block to all IO cells must be routed with equal delay to all cells, though the timing requirements are relaxed because the impedance code changes slowly (microsecond timescale).

The ZQ block is typically shared across all byte lanes within a PHY instance. It is usually placed centrally or at one end of the PHY, with digital code buses fanning out to all byte lanes.

### Q6. How does per-bit deskew work in the PHY, and what is its relationship to layout matching?

**Answer:**

Per-bit deskew is a fine-grained timing adjustment applied individually to each DQ bit within a byte lane. It compensates for skew caused by differences in routing length, via count, coupling environment, and process variation between individual DQ paths.

The deskew mechanism uses a digitally controlled delay line on each DQ path. The delay line consists of a series of unit delay cells that can be bypassed or included in the signal path via digital control bits. A typical implementation provides 5-7 bits of control, giving 32-128 delay steps with approximately 1-5 ps per step. The total delay range is 50-200 ps, sufficient to compensate for typical intra-byte skew.

During read training, the PHY sweeps the deskew delay for each DQ bit while monitoring the bit error rate. The optimal setting centres the DQS sampling point within each DQ's eye. This per-bit training can compensate for routing mismatches within the byte lane.

However, per-bit deskew has limitations that layout engineers must understand. First, the delay line adds parasitic capacitance to the signal path, which degrades the signal bandwidth and reduces the eye opening. More delay cells in the path means more parasitic load. Second, the delay line has finite granularity -- it cannot compensate for skew smaller than one step. Third, the delay range is limited, so if the layout-induced skew exceeds the trainable range, the system cannot achieve timing closure.

The relationship to layout matching is complementary: the layout should be designed to minimise intra-byte skew (ideally less than 50 ps), and the per-bit deskew compensates for the residual skew that layout matching cannot eliminate. This approach distributes the delay range across fine correction rather than gross compensation, maximising the available margin. If the layout engineer relies entirely on per-bit deskew to fix large mismatches, the delay line uses most of its range for gross correction, leaving insufficient range for PVT-induced drift during operation.

### Q7. What is the CA (Command/Address) training block, and how does it interact with the layout?

**Answer:**

The CA training block calibrates the timing of the Command/Address signals relative to the system clock (CK) at the DRAM. In LPDDR5, the CA bus operates at double data rate (both edges of CK), making timing calibration essential for reliable command delivery.

The CA training procedure (Command Bus Training, or CBT) works as follows: the memory controller puts the DRAM into CA training mode via a mode register write. The SoC then drives known CA patterns while sweeping the CA timing (adjusting a delay on the CA output path). The DRAM compares the received CA pattern with the expected pattern and reports pass/fail via a feedback mechanism (typically using DQ[6:0] to report results). The SoC identifies the passing window and sets the operating point at the centre.

The CA training block within the PHY contains a delay line on each CA output (or a shared delay for all CA signals within a channel), a pattern generator that produces the training patterns, a result comparator that reads the feedback from the DRAM, and a finite state machine that controls the sweep-and-centre algorithm.

For layout, the CA training block is placed near the CA IO cells. The CA signals must be length-matched to the CK pair within the channel, with the matching tolerance determined by the setup and hold times for the CA bus (tIS/tIH). Typically, CA-to-CK matching within plus or minus 200-300 ps of delay is required before training, and the training algorithm compensates for the residual offset.

The CA signals share a common delay adjustment in many implementations (all CA bits in a channel are shifted together), so the relative matching between CA bits must be handled by layout length matching. The layout engineer must ensure that all 7 CA signals within a channel are closely matched in length (within plus or minus 30-50 um) so that the single delay setting works for all bits.

The feedback path from the DQ bus back to the CA training controller must be reliable, as incorrect feedback would cause the training to converge on a non-optimal setting. This path typically uses the existing read data path infrastructure.

### Q8. How is the clock distribution organised within the PHY, and what are the critical layout requirements?

**Answer:**

Clock distribution within the PHY delivers multiple clock signals from the PLL to each byte lane, the CA lane, and the common control logic. The clock tree is one of the most critical structures in the PHY layout because clock jitter and skew directly impact timing margins.

The PLL generates several clock frequencies and phases. The primary output is the data-rate clock (or a divided version), which feeds the serialisers and deserialisers. The PLL also generates the CK output clock (which drives the DRAM), the WCK output clock, the DFI clock (for the controller interface), and multi-phase clocks for the serialiser mux stages.

The distribution topology is typically an H-tree or balanced tree structure for the high-speed clocks. The PLL output feeds a root buffer, which splits into two branches, each branch splits again, and so on until each byte lane receives a clock tap. The tree is designed so that every byte lane sees the same wire delay from the PLL. Matching the delay across branches is achieved by symmetric routing -- using the same metal layers, same wire widths, and same via stacks on each branch.

Critical layout requirements include delay matching between all branches, with a typical target of less than 5-10 ps of skew between the fastest and slowest byte lane. This requires geometric symmetry in the routing and matched loading (the same number and type of clock buffers at each tap point). Jitter preservation is also critical, meaning the clock tree must add minimal jitter to the PLL output. This requires clean power supply routing to the clock buffers, shielding of the clock routes from noisy signals, and minimising capacitive loading to keep buffer sizes reasonable. Duty cycle maintenance means the clock tree must not distort the duty cycle, which requires matched rise and fall times in the buffers and symmetric routing of differential clock pairs.

The CK and WCK output paths (from the PHY to the package bumps) require particularly careful routing because they drive off-chip and must meet the JEDEC specifications for jitter and duty cycle at the DRAM pins.

### Q9. What is the typical area breakdown of an LPDDR5 PHY, and which blocks dominate?

**Answer:**

The area of an LPDDR5 PHY varies with process node, implementation style, and feature set, but a typical breakdown for a single-channel PHY in a 5nm process is as follows.

IO cells (DQ, DQS, CA, CK, WCK drivers and receivers) typically consume 30-40% of the total PHY area. The IO cells are custom-designed analog blocks with large output transistors (for driving 40-50 ohm into the transmission line), ESD protection structures, and level shifters. Each DQ IO cell may be 20-40 um wide (along the die edge) and 60-100 um deep (from the die edge inward).

Serialisers and deserialisers, including the multi-phase clock muxing logic, consume approximately 15-20% of the area. These are high-speed digital circuits that must be placed close to the IO cells to minimise wire delay on the serialised data path.

FIFOs and clock domain crossing logic consume 10-15% of the area. The FIFO depth and width determine the memory requirements, which translate to register file or SRAM area.

The PLL/DLL occupies 5-10% of the total area but requires significant isolation space around it (guard rings, keep-out zones for digital logic), which effectively increases its area footprint.

Training logic (FSMs, pattern generators, comparators) consumes 10-15% of the area. This is predominantly digital logic that can be synthesised and placed with standard tools.

The ZQ calibration block, VREF generators, delay lines, and miscellaneous control logic consume the remaining 10-15%.

For a complete 4-channel LPDDR5 PHY (x32 interface), the total area is typically 2-6 mm^2 in a 5nm process. This is a substantial portion of the die area in a mobile SoC, which motivates aggressive optimisation of PHY layout density.

### Q10. How does the PHY handle multiple power domains, and what are the layout implications?

**Answer:**

An LPDDR5 PHY operates across multiple power domains that must be carefully managed in the layout. The primary domains are VDDQ (0.5V, powering the IO interface), VDD2 (1.05V, powering certain PHY analog circuits), VDD1 (1.8V, powering the core DRAM interface logic), and the SoC core voltage (typically 0.5-0.8V in advanced nodes, powering the digital logic including FIFOs and training FSMs).

The IO cells span two or three voltage domains: the output drivers and input receivers operate in the VDDQ domain, the pre-drivers and level shifters operate between VDDQ and the core domain, and ESD protection structures may reference VDD1. This multi-domain operation requires level shifters at every boundary between domains, power domain isolation cells for low-power modes (when VDDQ may be powered down while the core remains active), and separate power grids for each domain with dedicated decoupling.

Layout implications are significant. Each power domain needs its own set of power and ground rails, typically on different metal layers to avoid conflicts. The VDDQ grid is usually on upper metal layers (wider, lower resistance) because it carries the high transient currents from the output drivers. The core voltage grid feeds the digital logic and can use intermediate metal layers. VDD2 and VDD1 may share layers with appropriate isolation.

Guard rings between voltage domains prevent latch-up and reduce noise coupling. The VDDQ domain is particularly noisy due to the high-speed switching of the output drivers, and this noise must not couple into the VDD2 domain (which feeds the PLL/DLL) or the core domain (which feeds the FIFOs and training logic).

The power-up and power-down sequencing of the voltage domains must be supported by the layout -- isolation cells must be placed at every signal crossing between domains, and their placement must be considered during floorplanning to avoid routing congestion at domain boundaries.
